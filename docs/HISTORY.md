# How AxiomForge was built

[Türkçe](HISTORY.tr.md) · [Back to the README](../README.md)

AxiomForge grew in layers between 10 and 29 October 2026 (about 490 commits). Each layer fixed a weakness that the previous one exposed, usually found by running the real system rather than by reading code. This page tells that story in short; the detailed notes are in [`dev-notes/`](dev-notes/).

## The phases

| Phase | What was added | Why it was needed |
| --- | --- | --- |
| 1. Experiment loop | A model writes a scikit-learn experiment, runs it in an E2B sandbox and fixes its own code from the traceback (up to 3 tries). Results go to MLflow. | The simplest thing that works end to end. |
| 2. Agent graph | A LangGraph pipeline: literature search, three proposed plans, a **human approval** step, then the experiment. State lives in PostgreSQL. | Nothing should spend money or run code before a person agrees. |
| 2.5. Experiment memory | Past experiments are embedded in `pgvector`; the planner reads earlier failures and does not repeat them. | The agent kept proposing the same broken idea. |
| 3. Verifier and critique loop | The code is reviewed for data leakage; failed results go back to the experiment step with the critique (at most twice). | A passing script is not a valid experiment. |
| 4. Report agent and console | A workshop-style paper is written; a Next.js console shows the run live. | Results need to be readable. |
| 5–7. Scientific rigour | Models compared on the same split, imbalanced data handled, results averaged over split seeds, one data load per run, one isolated state per run. | A single split is an anecdote. |
| 8–9. Statistical decision and control group | The decision moved out of the language model into Python: paired tests over seeds, Holm correction, and every configured model also runs with library defaults (`Model__default`). | "Tuning helped" must be measured against an untuned control. |
| 10. Real data | Synthetic data was dropped. Real Hugging Face datasets are loaded through a verified loader block with preprocessing fitted on the training split only. | Synthetic data proves nothing about real behaviour. |
| 11. Paper gate | Deterministic rules reject overclaims and invented methods; key sentences are generated by Python and copied by the writer. | Live runs showed the writer repeating the same mistakes. |
| 12. Replication campaign | An engine with **no language model** tests a published claim on many datasets: per-dataset scores, Wilcoxon over datasets, Holm, Friedman, an evidence ledger and a report where every number points to the ledger. | One dataset cannot replicate a claim. |
| 13. Agentic campaigns | The graph can plan campaigns from a question or an arXiv paper, ask for approval, run them and write a meta paper; the mode is always chosen explicitly. | Connect the engine to the agents without giving a model spending power. |
| 14. Campaign extensions | Provenance (dataset revisions, library versions, specification digest), moderator analysis, a tuned protocol with default controls, arXiv intake, and a benchmark of 10 known claims (10 of 10 correct). | Make results reproducible and measure the system itself. |
| 15. A console for everyone | Plain-language summaries, confidence meter, charts, glossary, Turkish and English, dark theme, readable errors, access key and daily limit, cancel and retry, keyboard and screen reader support, browser tests, CI. | The first real user test: "too many numbers". |
| 16. Research agent | A closed loop that proposes its own hypotheses from results without inflating false discoveries: exploration and confirmation datasets, frozen registered hypotheses, one correction per session. Start, cancel, retry and live progress from the console. | Move from verifying given claims to proposing new ones, with statistical guarantees. See [`RESEARCH_AGENT.md`](../RESEARCH_AGENT.md). |

## What the real runs taught

Many of the decisive fixes came from running the system for real, not from tests that passed:

- **The referee must not be a language model.** A language-model referee made the rewrite loop unstable; deterministic checks plus ready-made sentences were reliable.
- **Rules conflict.** Two paper rules (state the leader in two sections, never repeat a sentence) together made a clean paper impossible until the sentences were made different on purpose.
- **A rule can fire on correct text.** "Was not supported" tripped the "supported" rule; negation is now understood.
- **A network blip must not kill a session.** A dropped sandbox connection ended a 17-minute research session because one exception type was not counted as a failed attempt. Now any exception of an attempt counts as one failed attempt.
- **A cancel must not save half a stage.** A live run showed that a cancelled stage left partial results that a retry would have treated as complete.
- **A language model can contradict itself.** In the first research-agent prompt about half of the hypotheses named the models in the wrong order; the protocol counted them as reversed or not confirmed instead of as discoveries, and the prompt was fixed.
- **Measure the system.** The false positive rate of the decision layer (2.1% in simulation, 0 of 45 with real models) and of the research protocol (3% against 24% for a naive adaptive agent) are measured with tools in the repository; see the [technical report](../TECHNICAL_REPORT.md).

## How it was developed

- Test-first for features, then **mutation checks**: the code is broken on purpose and a test must fail.
- One feature or fix per commit; documents in separate commits.
- Real LLM and sandbox runs are costly, so tests never call them; real runs were done deliberately and recorded.
- The project was developed with an AI coding assistant, which kept the handover notes in [`dev-notes/`](dev-notes/). The design decisions, the measurements and the limits are documented so that they can be checked.
